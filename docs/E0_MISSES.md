# E0 misses

Every planted toybench weakness that graderproof did not detect in E0 (prereg/0001), with the reason, from the per-task evidence (`artifacts/e0/evidence/`), the grader source (`toybench/tasks/<id>/grader/`), and the label (`toybench/labels.json`). A planted task counts as detected only through a witness-backed flag in its planted direction (DECISIONS.md D23). toybench is synthetic: these are weaknesses a planting agent wrote into small project-written tasks, not findings about any public benchmark.

Each explanation was drafted by an analysis agent that read only the files named above, and was checked against the evidence before it was committed. Counts and rates for E0 are in `artifacts/e0/results.json` and the README; this file holds no result numbers.

## What the misses have in common

- **Timing.** Timing weaknesses are the largest group of counted misses. graderproof's only timing operator (`pre-delay`) sleeps before the reference runs, so it never ages an output after it is written, never slows a script the grader times, and never reorders writes in a way the final file contents can show. Catching these needs post-write delays, slowed helper scripts, and a record of file-event order in the sandbox.
- **Brittle parsing.** The brittle-parsing misses are format strictness that no preserving operator exercised: CRLF line endings in CSV, and an integer where a float string was expected. In the CSV case the right variant existed but the extracted requirement compared exact text, so the two validators disagreed and the variant was excluded. Requirements that compare parsed values rather than raw text, and preserving operators for line endings and numeric types, would close them.
- **Loose matching.** The loose-matching miss needed a list argument with an extra element; the trajectory argument operator only edits strings.
- **Outside the written list.** The extra-slice misses need operators graderproof does not have: tampering with an input the grader recomputes from, swapping an identifier for another valid one, and changing output format in a way the grader silently skips.

## Counted misses (in_list slice)

### customer-totals (brittle-parsing, reject)

The grader splits `totals.csv` on LF and compares raw lines, so valid CSV using CRLF endings (the `csv.writer` default) or quoting every field is rejected. The closest variant was that CRLF case: a `model-preserving` rewrite dropping `lineterminator="\n"`, which the grader rejected. It did not count: the validators disagreed and it had no witness. The model review called it preserving, since the task never fixes a line terminator. The deterministic requirement witness called it violating, because extraction made `R2` a `file_equals` check against the reference output's exact LF text, normalized only by `strip`, which the CRLF file fails; `R4`, by contrast, tolerates a trailing carriage return. No deterministic variant used CRLF or full quoting. Extracting `R2` as a comparison of parsed CSV rows would let this variant validate and count as a witness-backed false reject.

### mean-rating (brittle-parsing, reject)

The grader compares `str(result)` with expected strings such as three point zero, so a correct solution that returns an int for a whole mean, as rounding `statistics.mean` does, is rejected although the task asks only for a number. The closest variant was the `model-preserving` rewrite to `statistics.fmean`, which, unlike `statistics.mean`, always returns a float. Both validators labeled it preserving and it was counted, yet its float results matched the grader's strings, so it passed, like every counted preserving variant. Extraction was not the cause: `R2` expects plain integers on the whole-mean probes and still held for float results, so it would hold for an int too. No variant changed the result's type while keeping its value; a preserving operator that returns an equal int for a whole mean would expose it on the grader's all-threes case.

### hosts-entry (timing, accept)

The instruction requires `hosts.bak` to be complete before `hosts` is touched, but the grader compares modification times with a one-second slack, so editing `hosts` first and immediately writing an exact original copy to `hosts.bak` passes. The closest variant, a `model-violating` reorder, appended first and then ran `cp`, copying the edited file, so the backup held the new line and the grader rejected it on content, a correct kill rather than a false accept. No operator saved the original before editing and wrote it to `hosts.bak` afterwards. Such a variant would also lack a witness: extraction reduced the ordering requirement `R4` to a content check, and the recorded outcome holds final contents but no write order, so every requirement would hold. Catching it needs an operator that defers the backup write but keeps its content, plus a write-order check on file events recorded in the sandbox.

### line-counter (timing, reject)

The grader runs `bin/countlines` on three thousand log files under a two-second limit the instructions omit, so a correct script calling `wc -l` once per file is rejected although the task timeout allows it. The closest variant, a `model-preserving` rewrite summing `wc -l` per file, was rejected by the grader. It did not count because the validators disagreed: the requirement witness, whose file-selection check only pattern-matches the script text, reported that all requirements hold, but the model review called it violating since the rewrite also dropped `dotglob`, skipping hidden `.log` files that the instructions include. The counted `pre-delay` variant passed because its sleep sits in `solve.sh`, not in the timed script. An operator that slows the generated script and changes nothing else, such as a per-file rewrite keeping `dotglob` or a delay inside `bin/countlines`, would yield a counted preserving variant the grader rejects.

### sales-report (timing, reject)

The grader rejects a report whose `generated_at` is more than five seconds old at grading time, so a correct program that writes the report and keeps working longer than that, within the time limit, is rejected. The closest variant was `pre-delay`, a preserving wrapper that sleeps before running the reference solution. It counted, with both validators agreeing and a witness, but the grader accepted it, so it showed no false reject. Its timestamp is taken after the sleep, leaving the report fresh, and the sleep is shorter than the five-second limit. Every generated wrapper puts its sleep before the original program runs, so no variant delays after the write. A new `post-delay` operator that sleeps after the original program exits, for a sizable fraction of the task time limit, should yield a counted preserving variant this grader rejects.

### meeting-invites (loose-matching, accept)

The grader's attendee check only confirms the required invitees are present, so extras such as `tom.becker@example.com` pass despite the instruction to invite nobody else. Requirement extraction was correct: `R3` requires exactly the listed invitees, checked by exact list equality. Yet no variant invited anyone extra. `traj-argument` only suffixed string arguments (title, date, times), never the attendee list. The closest were `model-violating` variants. One dropped Priya Nair, an omission the grader does catch. Another added her again via `add_attendees` to a guessed, nonexistent event, changing nothing, so the witness found every requirement held while the reviewer said violating, and the disagreement left it uncounted. A `traj-argument` mode that appends a new element to list arguments, here an uninvited directory address in the `create_event` attendees, should fail the exact list check, pass this grader, and supply the missing witness-backed false accept.

## Extra-slice misses (reported beside G5, not counted)

### booking-cancel (trusts-solution-identifier, accept)

The grader takes the booking ID from the solution's own last `cancel_booking` call and checks only that it belongs to Lin Zhao, never that it is the requested one, so cancelling the booking she asked to keep instead passes. The closest variants were a `model-violating` variant that also cancelled the kept booking after the requested one and a `traj-argument` variant that appended a suffix to the booking ID. Both were counted with witnesses, but the grader rejected them: with the extra cancellation, it took the kept booking as its target and found the requested one cancelled too, and the suffixed ID matches no booking. Requirement extraction was correct; no operator replaced the requested ID with the kept one. A `traj-argument` mode that swaps an identifier for another valid one seen in the reference run's tool results would catch it.

### iso-dates (parse-failure-skipped, accept)

The grader skips any case whose returned value `date.fromisoformat` cannot parse, so a non-ISO result such as an unpadded date is never checked. The closest variant came from `py-return-none`, which replaced `return date(year, month, day).isoformat()` with `return None`. It was counted but not accepted: the grader skipped every valid case, yet the edit also removed the `date(...)` call, the only check for nonexistent dates, so the variant returned `None` for the thirty-first of April instead of raising `ValueError`, and the invalid-input loop rejected it. The grader-accepted `py-constant` month-name changes do not involve the skip and were uncounted because the validators disagreed. Adding an output-format operator, such as one that drops zero padding while keeping the `date(...)` call, would yield a variant that the grader accepts but that the `equals` checks in `R2` through `R5` witness.

### meter-readings (oracle-from-mutable-input, accept)

The grader recomputes its expected totals from `readings.csv` at grading time, a file the solution can rewrite, so a solution that deletes a meter's rows there and omits that meter from `usage.csv` passes. The closest were variants from `out-drop-last-line`, `py-partial-loop` and `model-violating` that dropped the last meter's row from `usage.csv`, plus another `py-partial-loop` variant that skipped the last input row, only in memory. Both validators labeled these violating and they were counted, yet the grader rejected every counted violating variant: none writes to `readings.csv`, so the grader's recomputed expectation always matched the specification. The output transforms rewrite only `usage.csv`, and the code and model edits only read the input. An input-tampering operator that deletes a meter's rows from `readings.csv` and its row from `usage.csv` would expose the weakness, and the existing row-count and exact-content requirements, pinned to the reference output, would supply the witness.
